# MiniPhone

Минимальная консольная SIP-звонилка на Python 3.11+: один аккаунт, один звонок,
входящие/исходящие, звук в обе стороны, видео в отдельном окне, отключение микрофона.
Своя реализация SIP/UDP и SIP/WSS, Digest, SDP и управления звонком.
WebRTC-медиа (ICE, DTLS-SRTP) обслуживает системный GStreamer. Готовый SIP-клиент,
Linphone, PJSIP, браузер или веб-сервис не используются.

## Запуск на виртуалке

```sh
cd /home/user/miniphone
./run.sh --check
./run.sh --devices
./run.sh
```

В запущенной консоли:

```text
call 1001 video
call 1001 audio
answer
reject
hangup
mute
unmute
status
codecs
register
quit
```

`call НОМЕР` по умолчанию предлагает аудио и видео. Если собеседник принимает
только аудио, разговор продолжается без видео. `status` показывает регистрацию,
состояние звонка и счётчики переданных/принятых RTP/RTCP-пакетов и декодированных буферов.
Входящий вызов выводится в консоль и ожидает `answer` или `reject`.
В шаблоне автоответ выключен; включается `--auto-answer` или `media.auto_answer=true`.
На рабочей виртуалке .138 автоответ включён.
`quit` и Ctrl+C завершают разговор и снимают свою регистрацию.

## Настройка

`config.toml` — рабочий файл с правами 600. Не включайте его в публичные архивы.
`config.example.toml` — шаблон без настоящего пароля.
На виртуалке используется выбранный пользователем аккаунт `1002`.
Для него настроены WSS `wss://sip.test:7443/` и WebRTC PCMU/VP8.

В `[sip]`:

- `server`: IP или домен сервера, например `192.168.1.135` или `sip.test`.
- `port`: SIP-порт для режима UDP, обычно 5060.
- `transport`: `udp` для обычного SIP/RTP или `wss` для SIP/WSS и WebRTC.
- `wss_url`: полный WSS-адрес, например `wss://sip.test:7443/`.
- `tls_cert_sha256`: SHA-256 сертификата для доверенного самоподписанного сервера;
  пустое значение включает обычную проверку CA и имени сервера.
- `tls_ca_file`: необязательный путь к доверенному CA в формате PEM.
- `username`, `password`: именно SIP-учётная запись, не пароль Linux/SSH.
- `domain`: домен SIP-идентичности, если он отличается от адреса сервера.
  Пустая строка означает `server`. Запись hosts заменяет DNS, но не создаёт
  SIP-домен внутри сервера. Например, сервер доступен как `sip.test`, а
  существующий FreeSWITCH может требовать `domain = "192.168.1.135"`.
- `auth_username`: необязательное отдельное имя для авторизации.
- `local_port`: локальный SIP-порт, второй экземпляр должен использовать другой.
- `advertise_ip`: IP этого компьютера, доступный собеседнику; обычно выбирается автоматически.
- `register`: регистрация на сервере; без неё возможен прямой вызов
  `call sip:1001@192.168.1.139:5060 video`.

В `[media]`:

- `rtp_port`: чётный начальный порт. Используются четыре UDP-порта подряд:
  звук RTP/RTCP, затем видео RTP/RTCP. По умолчанию 40000–40003.
- `audio_codecs`, `video_codecs`: список и порядок предпочтения строго из разрешённых ниже.
- `video`: включить/отключить видео. Разрешение, fps, битрейт также настраиваются.
- `audio_source`, `audio_sink`, `video_source`, `video_sink`: локальные
  GStreamer-цепочки устройств, например `pulsesrc`, `pulsesink`,
  `v4l2src device=/dev/video0`, `autovideosink`.
  Это доверенная настройка администратора, не ввод удалённого SIP-абонента.
- `test`: тестовый тон и движущийся рисунок вместо устройств; полученные звук
  и видео декодируются, но не воспроизводятся. Этот режим проверяет передачу,
  а не физические микрофон, динамики и камеру.

После изменения конфигурации перезапустите программу.

## Аудио и видео

Разрешены только включённые на исходных скриншотах кодеки:

| Аудио          | Видео                                                                           |
| ------------------- | ------------------------------------------------------------------------------------ |
| PCMU (G.711 µ-law) | H.264 baseline/constrained baseline, level 3.1, packetization-mode=1                 |
| PCMA (G.711 A-law)  | VP8                                                                                  |
| G.722               | AV1 profile 0, один пространственный/временной слой |
| G.729               |                                                                                      |

Speex, GSM, iLBC на скриншоте выключены и здесь не предлагаются.
Opus, VP9 и другие кодеки приложение не объявляет и не выбирает, даже если
они есть в системных библиотеках. Если согласованный формат вне списка,
программа отклоняет его. G.729 передаётся без VAD (`annexb=no`); принимаются
обычные G.729-пакеты и SID через декодер. У G.722 RTP clock rate равна 8000,
хотя реальная частота звука 16000 Гц — это требование формата RTP.

Для видео нужен графический сеанс Linux. Запускайте `./run.sh` из терминала
рабочего стола виртуалки. Обычное SSH-подключение само по себе не передаёт
камеру, микрофон или окно видео на ваш Windows-компьютер. Пробросьте устройства
в виртуальную машину. Для Raspberry Pi можно явно задать источник камеры;
для некоторых модулей требуется системный `gstreamer1.0-libcamera` и
`video_source = "libcamerasrc"`.

Пока устройств нет:

```sh
./run.sh --test
```

## Установка и ARM

```sh
chmod +x install-debian.sh run.sh
./install-debian.sh
# отредактируйте config.toml
./run.sh --check
./run.sh
```

Исходники общие для x86_64/AMD64 и ARM. Python-код не содержит машинного кода
или путей вида x86_64. Библиотеки устанавливает пакетный менеджер под архитектуру
системы. Нет зависимостей pip и компиляции при установке. На свежей Debian нужны
Python/PyGObject, GStreamer с нужными системными плагинами и libbcg729.
Дистрибутивные пакеты плагинов содержат больше кодеков, чем использует приложение;
это не отдельные возможности звонилки. Полностью исключить лишние кодеки из
самих установленных пакетов можно только специальной сборкой GStreamer.

На Debian 13 x86_64 приложение проверено. ARM-сборка и реальное устройство
пока не проверены; на ARM сначала выполните проверки ниже. Для слабой платы
начните с 320×240, 10–15 fps и H.264/VP8. AV1 кодируется программно и может
оказаться слишком тяжёлым. Установка Windows в этой версии не подготовлена;
основная целевая платформа — Debian на x86_64 и ARM.

## Проверки

```sh
python3 -m unittest -v test_phone test_wss
python3 test_webrtc.py
python3 test_media.py
./run.sh --register-check
```

Первый набор проверяет Digest, SDP, SIP-вызовы в обе стороны, ACK, BYE, CANCEL,
отказ, занятость, повторный INVITE, неправильные теги диалога и AV1 RTP.
Второй реально кодирует/декодирует все семь кодеков между двумя UDP-сторонами,
проверяет RTP/RTCP в обе стороны и полный SIP-вызов с одновременным звуком и видео.
`--register-check` регистрирует и затем удаляет только собственный Contact.
Он использует SIP-порт из конфигурации: сначала завершите основной экземпляр.

## Границы этой версии

Проверена локальная IPv4-сеть. В UDP-режиме RTP/RTCP не зашифрован;
в WSS-режиме SIP защищён TLS, медиа — DTLS-SRTP с ICE. Настройки STUN/TURN
предусмотрены, но работа через внешние NAT не проверена. Нет обычного SIP/TCP
или SIP/TLS без WebSocket, DNS SRV, переноса звонков, удержания/re-INVITE, PRACK/100rel,
отложенного SDP, DTMF, телефонной книги, чата, записи и эхоподавления.
Для разговоров используйте гарнитуру. RTP-порты должны быть доступны между
клиентами или между клиентом и медиасервером. После потери видеопакетов картинка
восстанавливается на очередном ключевом кадре (примерно раз в 2 секунды);
в UDP-режиме расширенные RTCP PLI/FIR и повторная передача кадров не реализованы.
В WebRTC управление транспортом и RTCP выполняет GStreamer.
Это первая собственная реализация, не замена годам тестирования зрелого SIP-стека.

## Технические источники

- SIP: https://www.rfc-editor.org/rfc/rfc3261
- SDP offer/answer: https://www.rfc-editor.org/rfc/rfc3264
- AV1 RTP: https://aomediacodec.github.io/av1-rtp-spec/
- GStreamer: https://gstreamer.freedesktop.org/documentation/
- G.729 C API: https://github.com/BelledonneCommunications/bcg729

Сторонние бинарники в архив исходников не включены. libbcg729 распространяется
под GPL-3.0-or-later; её лицензионные условия относятся к распространению сборок
с этой библиотекой. Исходники чужих кодеков здесь не скопированы.

## Устройства(обновлено 16 октября)

Камера GENERAL WEBCAM подключена через штатный проброс веб-камеры VirtualBox.
Обычный USB-фильтр для неё выключен: через USB камера определялась, но не выдавала
кадры. В рабочем config.toml выбран /dev/video0 с захватом MJPEG и преобразованием
в сырые кадры. JPEG здесь — формат камеры, в SIP по-прежнему передаются только
H.264/VP8/AV1. Настоящее видео проверено через VP8/RTP, без записи на диск.
После полного выключения виртуалки может потребоваться повторное подключение
GENERAL WEBCAM в режиме веб-камер VirtualBox.

Аудио: Built-in Audio Analog Stereo (виртуальная карта Intel ICH). Источник
pulsesrc device=alsa_input.pci-0000_00_05.0.analog-stereo; выход
pulsesink device=alsa_output.pci-0000_00_05.0.analog-stereo. Dummy Output устранён.
Пользователь user добавлен в группы video и audio. Для уже открытого сеанса
рабочего стола может понадобиться выход из учётной записи и повторный вход.
Открытие аудиовхода и аудиовыхода проверено; слышимость нужно проверить в разговоре.
Запускать ./run.sh без --test из терминала рабочего стола Debian.

## Автоответ и загрузка

Рабочий аккаунт сейчас 1002 (изменён пользователем). В рабочей конфигурации
media.auto_answer=true: входящий принимается автоматически.

На этой виртуалке включён автоматический вход GDM под user: рабочий стол
открывается после загрузки без ввода пароля. Файл /etc/gdm3/daemon.conf;
исходная копия /etc/gdm3/daemon.conf.before-miniphone-autologin.
После входа /home/user/.config/autostart/miniphone.desktop запускает
/home/user/miniphone/run.sh в окне GNOME Terminal. Повторный запуск блокируется
flock. quit завершает приложение; оно снова стартует при следующем входе.
Перезагрузка гостевого Debian не выполнялась во время настройки; параметры
автовхода, desktop-файл, запуск терминала, регистрация и блокировка дубликата
проверены. Настройка не включает автоматический запуск VirtualBox на Windows
и не настраивает загрузку отдельной серверной виртуалки .135.

## WSS и WebRTC (обновлено 21 октября 2026)

На .138 уже настроены `transport="wss"`, `wss_url="wss://sip.test:7443/"`,
SIP-номер `1002`, автоматический ответ и существующий автозапуск через GDM/GNOME.
Запуск и команды те же: `cd ~/miniphone && ./run.sh`, затем `call 1001 video`
или `call 1001 audio`; `hangup` завершает звонок, `quit` выходит из программы.
Не запускайте второй экземпляр поверх окна из автозапуска.

В `[webrtc]` выбираются предлагаемые кодеки `audio_codec="PCMU"` (или `PCMA`)
и `video_codec="VP8"` (или `H264`). При входящем звонке выбирается доступный
кодек из этих четырёх и списков `[media]`. G.722/G.729/AV1 остаются в UDP-режиме;
в WebRTC эта версия их не предлагает. Opus и другие новые кодеки не добавлены.
H.264: baseline/constrained baseline, level 3.1, packetization-mode=1.
Внешний браузер и сервер веб-страницы для работы программы не нужны.

`ice_min_port=41000` и `ice_max_port=41100` задают диапазон портов ICE;
для локальной сети разрешите UDP между клиентом и FreeSWITCH.
`media.rtp_port` используется только обычным UDP-медиатрактом.
`stun_server` и `turn_server` пусты для LAN. Пароли TURN, как и SIP, храните
только в приватном config.toml. После изменения настроек завершите программу
командой `quit` и запустите снова.

Для отката транспорта замените в `[sip]` `transport="wss"` на `transport="udp"`.
Исходная рабочая конфигурация сохранена на .138 как `config.toml.before-wss`.
Установка WebRTC добавляет системный пакет `gstreamer1.0-nice`; pip не нужен.
SIP и WebSocket реализованы на стандартной библиотеке Python, а ICE, DTLS,
SRTP и кодеки — системными библиотеками GStreamer. Это не реализация всех
сетевых и криптографических протоколов с нуля на Python.

Самоподписанный сертификат проверяется по SHA-256, полученному через SSH.
При замене сертификата программа откажется передавать SIP-пароль до обновления
`tls_cert_sha256`. Получайте новое значение через доверенный доступ к серверу:

```sh
sudo openssl x509 -in /usr/local/freeswitch/certs/wss.pem -outform DER | sha256sum
```

На FreeSWITCH в `conf/sip_profiles/internal.xml` добавлены параметры
`apply-candidate-acl=localnet.auto` и `apply-candidate-acl=wan.auto` для ICE;
применены через `sofia profile internal rescan reloadxml`. Оригинал находится
рядом в `internal.xml.before-miniphone-webrtc`. Они разрешают ICE-кандидаты,
не отключая SIP-аутентификацию. На другом сервере проверьте WSS и ACL отдельно.

При обрыве WSS текущий вызов завершается, соединение и регистрация восстанавливаются.
Ошибка сертификата не приводит к переходу на незащищённый транспорт.
Сигнализация по WSS не означает, что медиа передаётся через этот TCP-порт:
для аудио/видео используется отдельное ICE/DTLS-SRTP соединение.

Проверены на Debian 13 x86_64: регистрация WSS, восстановление после разрыва,
отказ при неправильном сертификате, звонки WSS↔WSS и WSS↔UDP в обе стороны
через FreeSWITCH с PCMU/VP8. Прямые WebRTC-тесты также проверяют PCMA и H.264.
ARM пока не тестировался. Тесты используют синтетический звук и картинку;
слышимость микрофона и качество изображения проверяются отдельным живым звонком.

Камера USB2.0 HD UVC WebCam подключена к .138 через webcam passthrough
VirtualBox и доступна как /dev/video0. Существующая настройка video_source
подошла: MJPEG 640×480, 30 fps, декодирование jpegdec перед VP8.
Проверена передача реального изображения через WebRTC/VP8: на принимающей
стороне декодированы 62 кадра. Фото и видеофайлы не сохранялись.
После полного выключения VirtualBox может потребоваться снова подключить
эту камеру через меню Устройства → Веб-камеры. Для звонка: call 1001 video.
