# MiniPhone: перенос на другой Linux

Пакет для проверки, 21 октября 2026. Проверенная система — Debian 13 x86_64.
Нужны Python 3.11+, сеть до FreeSWITCH и доступ sudo для установки пакетов.
Установщик рассчитан на Debian/Ubuntu с apt; другие дистрибутивы требуют
ручной установки зависимостей. ARM64/ARMHF предполагают те же исходники
и пакеты своей архитектуры, но на ARM приложение ещё не проверялось.
Это исходники с установщиком, не автономный бинарник: для apt нужен интернет.

## Быстрый запуск

Распакуйте архив в домашний каталог обычного пользователя:

```sh
tar -xzf miniphone-linux-test-2026-10-21.tar.gz
cd miniphone
./install-debian.sh
nano config.toml
```

В config.toml замените username и password на SIP-номер и SIP-пароль
(не Linux/SSH). Например, укажите отдельный тестовый номер, уже созданный
на FreeSWITCH. Для параллельной проверки с .138 используйте другой аккаунт:
на .138 работает 1002. Если переносите именно 1002, сначала выполните quit
в старой звонилке. Не добавляйте вторую секцию [sip], редактируйте существующую.

Шаблон уже настроен на ваш FreeSWITCH:

```toml
[sip]
server = "192.168.1.135"
port = 5060
transport = "wss"
wss_url = "wss://192.168.1.135:7443/"
domain = "sip.test"
username = "CHANGE_ME"
password = "CHANGE_ME"
```

Остальные поля оставьте из шаблона. В нём уже есть SHA-256 сертификата
нынешнего сервера .135. Это публичный отпечаток, не пароль. Запись hosts
не требуется: сетевое соединение идёт по IP, sip.test используется как
SIP-домен. Для другого сервера измените server, domain, wss_url и TLS-настройки.
Если сертификат .135 заменён, получите новый отпечаток через доверенный SSH;
не отключайте проверку сертификата. Об этом подробнее в REFERENCE.md.

После сохранения:

```sh
./run.sh --check
./run.sh --devices
./run.sh
```

Ожидайте Registered: ВАШ_НОМЕР@sip.test. В консоли:

```text
call 1002 audio
call 1002 video
answer
reject
hangup
status
quit
```

Каждая строка — отдельная команда. Примеры вызовов 1002 предназначены для
нового отдельного тестового аккаунта. Не звоните на свой собственный номер.
Для обычного разговора на другом телефоне можно использовать call 1001 video.
Входящие вызовы принимаются командой answer. Для автоответа установите
media.auto_answer=true и перезапустите. Ctrl+C или quit закрывает программу.

## Камера и звук

В шаблоне используются autoaudiosrc, autoaudiosink, autovideosrc,
autovideosink. Устройства из старой виртуалки не зафиксированы в конфигурации.
Запускайте программу от обычного пользователя в терминале рабочего стола:
для показа видео нужен графический сеанс. SSH сам по себе окно не показывает.

Если автоматический выбор не подходит, выполните ./run.sh --devices и задайте
соответствующие цепочки в существующей секции [media]. Пример для обычной V4L2
камеры и PulseAudio/PipeWire:

```toml
audio_source = "pulsesrc"
audio_sink = "pulsesink"
video_source = "v4l2src device=/dev/video0"
video_sink = "autovideosink"
```

У некоторых камер захват MJPEG надо указать явно, если они поддерживают формат:

```toml
video_source = "v4l2src device=/dev/video0 io-mode=2 ! image/jpeg,width=640,height=480,framerate=30/1 ! jpegdec"
```

Это формат захвата камеры, не дополнительный кодек звонка. Для виртуалки
подключите камеру через VirtualBox → Устройства → Веб-камеры. Проверьте права
на /dev/video0; при необходимости добавьте пользователя в группу video и
перезайдите в сеанс. Если камеры нет, звоните командой call НОМЕР audio.

## Проверка без камеры и микрофона

Сначала завершите запущенный экземпляр через quit. Затем:

```sh
./run.sh --test
```

Этот режим передаёт тестовый тон и движущуюся картинку, а принятые потоки
декодирует без вывода на устройства. Он проверяет сеть и кодеки, а не слышимость.
Для отдельной проверки регистрации: ./run.sh --register-check (основной
экземпляр должен быть закрыт; после проверки регистрация снимается).

Проверки без регистрации и физических устройств:

```sh
python3 -m unittest -v test_phone test_wss
python3 test_webrtc.py
python3 test_media.py
```

В WebRTC доступны PCMU/PCMA и VP8/H.264. В UDP-режиме дополнительно доступны
G.722/G.729/AV1. Для UDP смените transport на udp; port=5060. Настройки
WebRTC находятся в [webrtc], настройки устройств — в [media].
По умолчанию локальные ICE-порты 41000–41100/UDP; в обычном RTP-режиме
40000–40003/UDP. Сервер должен быть доступен по 7443/TCP для WSS или 5060/UDP.
NAT через интернет не проверялся; тестируйте сначала в локальной сети.

## Что не переносится автоматически

Этот пакет не меняет сервер FreeSWITCH, не создаёт SIP-аккаунты и не включает
автовход в Linux. Автозапуск и проброс камеры VirtualBox со старой .138 тоже
не переносятся. Сначала проверьте ручной запуск на новом компьютере.
Для слабого ARM начните с width=320, height=240, fps=10 и VP8/H.264.
Windows DLL, бинарники x86 и рабочие пароли в пакет не включены.

REFERENCE.md содержит подробности реализации и историю исходной виртуалки;
описанные там настройки .138 не применяются к новой машине автоматически.
TESTED.md перечисляет ранее выполненные проверки. SHA256SUMS позволяет проверить
файлы после переноса командой sha256sum -c SHA256SUMS.
